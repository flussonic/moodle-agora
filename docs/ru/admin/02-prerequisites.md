Документ считает, что у вас уже есть **работающий сервер Agora** и
**работающий сайт Moodle 4.5 LTS** (PHP — той версии, которую требует ядро).
Всё остальное описано здесь по шагам.

Соберите заранее четыре вещи.

**Доступ администратора Moodle.** Право администрирования сайта, доступ к
файловой системе сервера Moodle (положить каталог в `mod/`) и возможность
запустить обновление базы.

**Доступ оператора Agora.** Учётная запись консоли Agora с ролью
`superadmin` — только она умеет заводить новые учётные записи. Ролью пониже
служебные записи для плагина не создать.

**Доступ к репозиторию плагина.** Адрес git-репозитория `mod_agora` (или архив
его каталога) — из него вы возьмёте код в разделе
[Установка и обновление плагина](05-install.md).

**Сеть в обе стороны.** Нужен доступ:

| Откуда | Куда | Зачем |
|---|---|---|
| Сервер Moodle | Сервер Agora | списки эфиров и шаблонов, билеты, состояния эфиров, история просмотра |
| Сервер Moodle | Узлы раздачи видео | кадр-обложка для карточки элемента и границы записи (начало и конец архива) — без них запись закончившегося эфира открывается с живого края, где пусто; сервер Agora отвечает на оба запроса переходом на узел |
| Браузер слушателя | Сервер Agora | страница плеера |
| Браузер слушателя | Узлы раздачи видео | само видео; медиа идёт мимо Moodle — сервер его не проксирует |

*Узел раздачи* — сервер, с которого зритель забирает видео. Их может быть
несколько, и это часто другие адреса и другие правила межсетевого экрана, чем у
самого сервера Agora.

**Одинаковый видимый адрес слушателя с обеих сторон.** Билет по умолчанию
привязан к адресу слушателя. Адрес, который видит Moodle, и адрес, который
видит узел раздачи, должны совпадать. Если между слушателем и одной из сторон
стоит прокси или NAT, а между слушателем и другой — нет, отказ получит сам
законный слушатель. Как это чинится — в разделе
[Неполадки](10-troubleshooting.md).
